# 服务端部署说明（把进销存搬到服务器 / NAS，可选）

> 单机（Windows）用户不需要看这份文档，直接跑工作台就行。
> 本目录是给「想 7x24 开着服务、手机在外面也能用」的进阶用户准备的。

## 文件说明

- `pocketbase.service` —— Linux systemd 单元（推荐方案，少一层依赖）
- `docker-compose.yml` —— Docker 方案（可选；镜像需选 arm64/amd64 对应、维护中的 PocketBase 镜像）
- `Caddyfile` —— HTTPS 反代模板
- `backup.sh` —— 每日备份脚本（打包 pb_data，保留 30 天）

## 方案 A：二进制 + systemd（推荐）

PocketBase 是单文件程序，从官方 Releases 下载对应架构的包（如 `linux_amd64` / `linux_arm64`）：

1. 上传解压：`/opt/pocketbase/pocketbase`（`chmod +x`）
2. 把本机 `jxc/pb_data` 整个目录拷到 `/opt/pocketbase/pb_data`（数据全在这）
3. 修改 `pocketbase.service` 里的路径 → `cp 到 /etc/systemd/system/`（先转 LF：`sed -i 's/\r$//' pocketbase.service`）
4. `systemctl daemon-reload && systemctl enable --now pocketbase`
5. 验证：`curl http://127.0.0.1:8090/api/health`

## 方案 B：Docker

- 把 `docker-compose.yml` 里的 `image` 换成可用的 PocketBase 镜像
- `docker compose up -d`，数据卷指向 `./pb_data`

## 外网访问

1. 确认家里宽带是否真公网 IP（很多是 CGNAT，需要 IPv6 或内网穿透）
2. 路由器端口映射：非标端口 → 服务器内网 IP（Caddy 的 HTTPS 端口）
3. 域名 + DDNS；Caddy 自动签证书（80/443 被封时用 DNS challenge）
4. 安全建议：管理通道走 Tailscale/WireGuard 这类内网穿透，公网只开业务端口

## 手机端

- 安卓壳 App 源码在 `jxc/android/`：改 `MainActivity.java` 里的 `DEFAULT_URL` 为服务器地址，重新打包
- 或个人用户直接用浏览器访问 + 「添加到主屏幕」也可以

## 备份

- `backup.sh` 配 cron 每天 03:30：打包 `pb_data` 到备份盘，保留 30 天
- 建议再同步一份到别的机器（scp/rsync）
- 数据库放 SSD，别放 eMMC/U 盘
